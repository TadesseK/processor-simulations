# Changes to the supplied simulator

The stage module names are retained. The original state representation assigned mutable fields to newly created `namedtuple` classes rather than instances. Several fields could remain class descriptors, and the code relied on type checks to distinguish values from tags. I replaced that representation with dataclasses for instructions, operands, ROB entries, execution tasks, and completed results. The cycle controller now passes one coherent machine state to each stage.

| Module | Added behavior and repairs |
| --- | --- |
| `init.py` | Parse the full hardware table, ROB capacity, optional issue width, register/memory initialization, all case-insensitive ISA instructions, commas, and two-digit register names. Add explicit resource, register, and address validation. |
| `issue.py` | Issue up to the configured width sequentially, stop on the first structural hazard, capture sources before renaming each destination, and expose within-bundle RAW/WAW/WAR dependencies. Implement one-bit prediction and the eight-entry tagged BTB. Read completed live ROB values without waiting for a second broadcast. Preserve R0. |
| `exe.py` | Dispatch ready instructions out of order by dynamic age. Advance each execution exactly once per cycle, make integer/address units unpipelined, pipeline FP units, and honor configured FU counts and latencies. Implement BEQ as well as BNE, correct word offsets, and branch resolution at EX completion. The starter's address counter could stall indefinitely when EX latency exceeded one. |
| `mem.py` | Search all older stores for the newest known matching address, wait for matching store data, forward in one cycle, and release completed load queue entries. Allow speculative bypass of unknown store addresses and recover on alias violations. Keep physical memory accesses single-port and nonpipelined. |
| `wb.py` | Broadcast one result per cycle, update the producing ROB entry, and wake tagged consumers. Keep RAT mappings until their actual writer commits or recovery rebuilds them. This fixes the starter's WAW error, where an older broadcast overwrote a younger RAT mapping. |
| `commit.py` | Retire one ROB-head instruction per cycle with real recorded commit cycles. Update registers only at commit. Start a store's memory access only at the ROB head, retain its queue entry until completion, and write memory when it retires. This replaces premature store writes, early dequeue, the misspelled store tag field, an uncalled committability function, and unsafe ROB indexing. |
| `simulator.py` | Coordinate stages as COMMIT, WB, MEM, EX, ISSUE with explicit ready-cycle boundaries. Use unique dynamic tags with bounded ROB occupancy. On recovery remove wrong-path ROB/RS/LSQ/FU/result state, cancel wrong-path memory work, rebuild the RAT from surviving writers, and resume fetch at n+2. Preserve squashed status rows, with truncated interrupted intervals. |
| `main.py`, `print_status.py` | Add an input-path CLI, width override, explicit legacy byte-offset mode, bounded runs, text/JSON outputs, all register values, nonzero memory, and actual stage/status rows. Fix termination to wait for both the program and ROB. |
| `tests/`, `test_cases/`, `run_experiments.py` | Add independent architectural interpretation, directed timing/hazard tests, exact original fixtures, normalized branches, both sample-report programs, all four issue widths, and reproducible output artifacts. |

The original source headers identify Qing and dates in May 2017. The work here is a revision of that supplied implementation and its stage organization. The original assignment and sample report are the specifications; no third-party implementation was used.

The sample report broadens writeback and commit with issue width, reports in-order execution, omits branch prediction for width greater than one, and permits overlapping memory transactions. Those choices conflict with the assignment's processor description. This implementation widens ISSUE only, executes ready operations out of order, predicts branches at every width, and preserves the one-CDB and single-port memory constraints. Single-instruction commit is retained from the base model and stated explicitly because the handout does not assign a separate commit width.
